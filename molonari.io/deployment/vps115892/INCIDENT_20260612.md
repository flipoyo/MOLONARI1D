# Incident MOLONARI.io - 2026-06-12

## Symptôme

Le site molonari.io est devenu inaccessible en HTTPS.

Les navigateurs retournaient :

```text
ERR_CONNECTION_REFUSED
```

## Diagnostic

Nginx ne démarrait plus.

Erreur observée :

```text
cannot load certificate
/etc/letsencrypt/live/molonari.io/fullchain.pem
```

L'ensemble de la hiérarchie Let's Encrypt avait disparu :

```text
/etc/letsencrypt/live/
└── README
```

La commande :

```bash
certbot certificates
```

retournait :

```text
No certificates found.
```

## Investigation

Aucune connexion SSH administrateur n'a été observée entre le 3 juin et le 16 juin.

Aucun redémarrage du serveur n'a eu lieu depuis le 29 mai.

Les journaux montrent qu'au moment de l'incident :

* Postfix ne trouvait plus son certificat TLS ;
* Nginx ne trouvait plus son certificat TLS.

L'incident semble donc avoir affecté plusieurs services simultanément.

## Cause racine

Inconnue.

Les hypothèses les plus probables sont :

* suppression ou altération de la configuration Let's Encrypt ;
* restauration partielle du système ;
* interaction avec la gestion automatisée des certificats (ISPConfig / Certbot).

Aucune preuve d'intrusion n'a été trouvée.

## Remédiation

1. Réactivation temporaire HTTP.
2. Recréation du certificat :

```bash
certbot certonly --webroot \
  -w /var/www/html/molonari.io/wordpress \
  -d molonari.io \
  -d www.molonari.io
```

3. Réactivation HTTPS.
4. Validation :

```bash
nginx -t
certbot renew --dry-run
```

## Prévention

* Sauvegarde régulière de `/etc/nginx`.
* Sauvegarde régulière de `/etc/letsencrypt`.
* Documentation de l'infrastructure VPS.
